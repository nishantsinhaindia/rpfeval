# Non-Functional Requirements Quality Checklist: Agentic RFP Evaluation and Supplier Ranking

**Purpose**: Check whether the spec's non-functional requirements are complete, clear, consistent, and measurable. Areas covered: determinism, reliability and error handling, traceability and explainability, performance, input validation, API-key security, and deployability.
**Created**: 2026-10-25
**Feature**: [spec.md](../spec.md)
**Scope**: spec.md and constitution v1.0.0 (plan.md and tasks.md do not exist yet). Intended as a standard-depth gate before `/speckit-plan`.

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

## NFR Definition & Traceability

- [ ] CHK001 - Are NFR-01 to NFR-10 defined anywhere in the spec, each with an ID, a statement, and a measurable target? The FRs and SCs cite them, and the Input line says they are "incorporated below", but the spec has no NFR section and the source brief does not define them either. [Gap, Traceability, Spec §Input]
- [ ] CHK002 - Once defined, does each NFR map to at least one measurable success criterion and have a single, clear scope? NFR-04 (reliability) is cited only by FR-012, and no SC claims it. NFR-07 is cited for two separate concerns: data retention (FR-035) and credentials (FR-036, SC-010). [Traceability, Ambiguity, Spec §FR-012, §FR-035, §FR-036, §SC-005, §SC-010]

## Determinism

- [ ] CHK003 - Is the limit of the determinism guarantee stated explicitly? Results are guaranteed identical only from validated scorecards onward; re-running the AI on the same PDFs may give different scores. [Clarity, Spec §FR-026, §SC-003, §Assumptions]
- [ ] CHK004 - Is the AI's "most repeatable (least random) setting" a verifiable requirement rather than only an assumption, in line with the temperature-0 rule in Constitution Principle II? [Consistency, Spec §Assumptions, Constitution §II]
- [ ] CHK005 - Is determinism required for the validation/normalization step itself, so that identical raw AI responses always produce the same validated scorecard and the same warnings? FR-026 only covers the steps after validation. [Gap, Spec §FR-015, §FR-016, §FR-026]
- [ ] CHK006 - Is "values that are mathematically equal MUST compare as equal" defined by an objective rule, either exact arithmetic or a stated tolerance? Is that rule reconciled with "full precision" storage, comparison, and the way numbers are written in the JSON export? [Ambiguity, Conflict, Spec §FR-026, §FR-027, §FR-032, §Edge Cases]
- [ ] CHK007 - Is a deterministic order required for every list in the output (warnings within and across suppliers, suppliers in run details and JSON, risks)? The order should not depend on which supplier's AI call finished first. [Gap, Spec §FR-016, §FR-030, §FR-032, Constitution §II]
- [ ] CHK008 - Is the "document truncated" limit a fixed bound with a stated unit (characters, pages, or tokens), so the same document always truncates at the same point? [Clarity, Spec §Edge Cases]

## Reliability & Error Handling

- [ ] CHK009 - Is "usable response" defined? Does the spec say which response is normalized when the first attempt is partly valid but the retry is malformed or fails, or the other way round? [Ambiguity, Spec §FR-015, §FR-019]
- [ ] CHK010 - Does the spec say clearly which defects trigger the single evaluation retry and which are only normalized? FR-014's trigger list leaves out unknown or duplicate criterion IDs, output wrapped in extra text, a mismatched supplier name, and missing evidence. [Clarity, Spec §FR-014, §Edge Cases]
- [ ] CHK011 - Is "service busy" defined by error class (rate limit, overload, server error, network error, quota or billing exhaustion), with each class mapped to busy-retry, failed call, or no retry? Do the "about 5, 10, 20 seconds" waits have tolerances? Is a longer wait requested by the service covered? [Ambiguity, Spec §FR-014]
- [ ] CHK012 - Is the worst-case time per supplier and per run bounded? FR-014 does not say whether the 90-second limit applies to each busy resend. If it does, a single attempt could take about 4 × 90 s plus 35 s of waits, which exceeds SC-002's "up to 90 seconds plus about 35 seconds". [Ambiguity, Conflict, Spec §FR-014, §SC-002]
- [ ] CHK013 - Is a supplier whose document passed the FR-007 checks but cannot be read during the run (FR-012) scored and ranked the same way as an "evaluation failed" supplier (FR-019)? Does it count toward "no supplier received a usable response" (FR-013)? [Consistency, Spec §FR-012, §FR-013, §FR-019]
- [ ] CHK014 - Must a run's results be stored all-or-nothing? Are the stored state, the history entry, and the user message defined for the case where storage fails partway? [Gap, Recovery, Spec §FR-013, §FR-033]
- [ ] CHK015 - Can "marked FAILED the next time the application starts" guarantee "never left RUNNING indefinitely", given that closing a browser tab does not restart a hosted app? Is a staleness timeout or other detection trigger needed? [Conflict, Spec §FR-013, §Edge Cases]
- [ ] CHK016 - Are requirements defined for concurrent use of the open public instance: runs at the same time, criteria edited during another user's run, and simultaneous writes to the data store? [Gap, Coverage, Spec §Assumptions, §FR-002, §FR-008]
- [ ] CHK017 - Is a run-level indicator required when most suppliers failed (e.g., only 1 of 4 usable), so that a COMPLETED status does not suggest a more reliable leaderboard than it is? [Edge Case, Spec §FR-013, §FR-019, §FR-028]

## Traceability & Explainability

- [ ] CHK018 - Is FR-018 (keep a non-zero score that has no evidence) reconciled with Constitution Principle III ("every criterion score MUST cite evidence")? Either amend the constitution or record it as a deviation in the plan's Complexity Tracking. [Conflict, Spec §FR-018, Constitution §III]
- [ ] CHK019 - Is the evidence-matching rule (spacing and case normalization, partial quotes, ellipses, minimum quote length) defined in FR-017 rather than only in SC-007? Is there a named Criterion Result flag for "evidence not found in document"? [Clarity, Gap, Spec §FR-017, §SC-007, §Key Entities]
- [ ] CHK020 - Is the set of warnings consistent and complete? Does every fix produce exactly one warning with its own issue type in the Validation Warning entity? This covers text-to-number conversion, an ignored supplier name, extracted wrapped output, unknown or duplicate IDs, and evaluation failed. The mismatched-supplier-name edge case currently mentions no warning. [Consistency, Spec §FR-015, §FR-016, §SC-005, §Key Entities, §Edge Cases]
- [ ] CHK021 - Must the exported JSON carry enough information for SC-004's hand check on its own: a schema version, field definitions, and the formulas and tie-break rules used (or a rules version)? [Gap, Traceability, Spec §FR-032, §SC-004, Constitution §III]
- [ ] CHK022 - Must each run record the AI model identifier, its settings, and the prompt or prompt version, so past AI judgments can be traced to how they were produced? [Gap, Traceability, Spec §FR-033a, §Assumptions]
- [ ] CHK023 - Does the AI Attempt Record cover busy-retry resends, or only the first attempt and the evaluation retry? [Completeness, Spec §FR-014, §FR-033a, §Key Entities]
- [ ] CHK024 - Is the display rounding rule fully specified, including how halves round? Must the tie-break explanation show extra precision when two different PPIs display the same value (e.g., 82.501 and 82.503 both shown as 82.50)? Otherwise "PPI decided" appears to contradict the displayed values. [Clarity, Edge Case, Spec §FR-027, §FR-031, §US2-AS3]
- [ ] CHK025 - Does the spec say how users are told that rank follows PPI rather than absolute score when the two orderings disagree? [Clarity, Gap, Spec §FR-028, §FR-031]

## Performance

- [ ] CHK026 - Is SC-002 measurable as written? Is its end point defined (leaderboard visible, or run stored as COMPLETED)? Are the AI-service latency conditions it assumes documented? [Clarity, Assumption, Spec §SC-002]
- [ ] CHK027 - Are performance targets defined for the 10-supplier maximum, or is it stated that none apply? Current targets cover only 4 suppliers. [Gap, Spec §FR-005, §SC-002, §Assumptions]
- [ ] CHK028 - Are response-time expectations defined for operations that do not call the AI: validating up to 10 × 10 MB of uploads, opening a growing run history, reopening a past run, and producing the JSON download? [Gap, Spec §FR-007, §FR-032, §FR-034]
- [ ] CHK029 - Is the list of per-supplier progress states complete rather than "e.g., waiting, evaluating, done, flagged"? Does it include retrying, busy-waiting, and failed, and is the progress refresh rate stated? [Clarity, Spec §US1-AS3, §FR-011, §SC-002]

## Input Validation

- [ ] CHK030 - Are the file checks precise? This means deciding "not a PDF" by file content rather than extension (consistent with the "renamed to .pdf" edge case), defining 10 MB in bytes, and stating whether files at exactly 10 MB or exactly 200 characters are accepted. [Clarity, Edge Case, Spec §FR-007, §Edge Cases]
- [ ] CHK031 - Is "password-protected" defined: a password needed to open the file, or permission-only encryption that still allows text extraction? Is a corrupted or truncated PDF rejected before the run (FR-007) or treated as a failure during the run (FR-012)? [Ambiguity, Spec §FR-007, §FR-012]
- [ ] CHK032 - Are the supplier-name rules complete? This covers maximum length, allowed characters, which characters count as "spaces" (tabs, non-breaking and other Unicode whitespace), and the case-folding and sort order for non-ASCII letters, used both in duplicate detection and in the A–Z tie-break. [Clarity, Spec §FR-007, §FR-025, §Assumptions]
- [ ] CHK033 - Is "today" for submission-date validation tied to a stated timezone? Server and user can disagree near midnight. Are a lower bound and the accepted date format specified? [Ambiguity, Spec §FR-007, §Assumptions, §Edge Cases]
- [ ] CHK034 - Are validation rules for individual weight edits specified (non-integer, negative, over 100, an active criterion with weight 0), in addition to the rule that the total must equal 100? [Gap, Spec §FR-002, §FR-003, §Assumptions]
- [ ] CHK035 - Are the content and timing of rejection messages specified? A message should name the file or supplier, the reason, and the limit broken, and the spec should say whether messages appear on upload or on Evaluate. FR-005 defines no message for more than 10 files. [Measurability, Gap, Spec §FR-005, §FR-007, §SC-006]
- [ ] CHK036 - Are requirements defined for instructions embedded in a supplier's document (prompt injection), so that document text is judged as content and never followed as instructions? [Gap, Security, Spec §FR-009, §FR-010]

## Security: API Keys & Retained Data

- [ ] CHK037 - Are requirements defined to keep credentials out of every runtime output? This covers error and configuration messages, warnings, stored failure reasons, raw AI responses, the JSON export, logs, and anything sent to the browser. [Gap, Spec §FR-032, §FR-033a, §FR-036]
- [ ] CHK038 - Is "missing credentials" defined: absent, empty or whitespace, or still the placeholder from the example file? Is the content of the configuration message specified so that it reveals no secret value? [Clarity, Spec §FR-036, Constitution §Technology & Data Constraints]
- [ ] CHK039 - Are credentials that are present but rejected (invalid, expired, revoked) handled separately from missing ones? Otherwise they go through FR-014's retry path, fail every supplier, and end the run FAILED with a misleading reason. [Gap, Exception Flow, Spec §FR-014, §FR-036, §Edge Cases]
- [ ] CHK040 - Does SC-010's repository scan have a defined scope (full git history and all branches, not only the current files) and a stated pass criterion? [Measurability, Spec §SC-010]
- [ ] CHK041 - Is the accepted cost-abuse risk of an open public URL limited by any documented control or operational assumption beyond the 10-suppliers-per-run cap, such as a spending limit at the AI provider? [Assumption, Spec §Assumptions]
- [ ] CHK042 - Is FR-035 (no full document text retained) reconciled with the stored evidence excerpts and raw AI responses, which may contain large amounts of document text? Is the point at which uploads are discarded defined for FAILED and interrupted runs too? [Consistency, Spec §FR-035, §FR-033a, §FR-013]

## Deployability

- [ ] CHK043 - Is "first start" defined (no data store, or an empty criteria table)? Must seeding be idempotent and never overwrite criteria users have edited? Is the behavior defined when a new deployment finds a data store with an older structure? [Clarity, Gap, Spec §FR-004, §Assumptions, Constitution §Technology & Data Constraints]
- [ ] CHK044 - Is the required deployment configuration listed (secret names, model choice, adjustable limits), with each item marked required or optional and given a default? [Completeness, Gap, Spec §FR-036, §Assumptions]
- [ ] CHK045 - Do requirements such as 10 × 10 MB uploads and the SC-001 and SC-009 timings account for the hosting platform's limits: memory, ephemeral storage, and apps that sleep when idle and need a cold start? [Assumption, Dependency, Spec §Assumptions, §SC-001, §SC-009]
- [ ] CHK046 - Must the SC-008 automated checks run without network access or AI credentials, as the constitution's merge gate requires? [Consistency, Spec §SC-008, Constitution §VII, §Development Workflow]
- [ ] CHK047 - Are the brief's deliverables (a README with setup steps and the required secrets, a sample exported JSON, and a public URL) captured as requirements or explicitly ruled out of scope? [Gap, Traceability, Spec §FR-037, Source brief §10]
